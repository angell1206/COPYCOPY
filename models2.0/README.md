# models2.0 — trained triage classifier

The **version 2.0 / 2.1** machine-learning triage model that powers the Streamlit
app's ML triage layer. The transparent keyword rules (`../triage_rules.py`) are a
separate evidence layer kept alongside it for operator cross-checking.

> ⚠️ Do not modify the legacy `models/` folder. All model work happens here.

## Contents

| File | Purpose |
| --- | --- |
| `helpline_triage_model.joblib` | Trained pipeline: word (1–2) + char_wb (3–5) TF-IDF → balanced Logistic Regression (C=3). |
| `triage_model.py` | Inference helper: `load_model()`, `predict_transcript()`. |
| `train_model.py` | Reproducible training; writes the `.joblib` artefact. |
| `evaluate_model.py` | Leakage-free grouped held-out evaluation + grouped CV; writes the report files. |
| `augmentation_v2_1.csv` | Curated, rubric-consistent examples closing a "being followed / send help" coverage gap. |
| `evaluation_report_v2_1.json`, `confusion_matrix_v2_1.csv` | Latest honest metrics (regenerated by `evaluate_model.py`). |

## Labels (routing, not severity)

- `PRIORITY_REVIEW` — potentially urgent; prioritise prompt human assessment.
- `SUPPORT_REVIEW` — support/reporting need; route to suitable support.
- `UNCLEAR_REVIEW` — ambiguous/insufficient context; clarify, do not assume safe.

## Reproduce

```bash
python models2.0/train_model.py       # retrain + overwrite the .joblib artefact
python models2.0/evaluate_model.py --save   # honest metrics -> report files
```

`train_model.py` fits the **shipped** artefact on all training data
(`../data/calls_train_v2.csv` + `augmentation_v2_1.csv`). `evaluate_model.py`
reports metrics from a separate grouped (by `scenario_family`) held-out split so
there is no family leakage; augmentation is added to the train side only.

## Latest metrics

From `evaluation_report_v2_1.json` (grouped held-out split, seed 42):

- Held-out accuracy ≈ **0.94**, macro F1 ≈ **0.94**, PRIORITY recall **1.00** (52 rows).
- Grouped 5-fold CV macro F1 ≈ **0.88** (sd ≈ 0.05).

These are uncalibrated scores on synthetic data, **not** evidence of real-world
performance. The frozen `calls_fresh_eval_36.csv` named in the dataset guidelines
is absent from the repo, so a grouped held-out split is used instead.

## Notes / fixes in v2.1

- The previously shipped artefact was **word-only** despite the comparison report
  selecting a **word + character** model; retrained to the word+char config,
  which generalises better to romanized Hinglish and sub-word variants.
- Added curated multilingual augmentation so present-tense "being followed /
  please send help" transcripts are no longer classified `UNCLEAR_REVIEW`,
  while hypothetical/quoted/resolved mentions stay `UNCLEAR_REVIEW`.
- `load_model()` suppresses scikit-learn `InconsistentVersionWarning`; retrain
  with `train_model.py` to repickle under your local scikit-learn.

## Safety

Decision support only. Must not auto-dispatch, escalate, or close a case. Every
prediction requires human verification of the transcript, current danger, and
caller location.
